## 3. 原因の切り分け（**仮説は2回とも実測に否定された**）

推測で止めず、否定されるたびに次を測った。その記録をそのまま残す。

1. **`.next/standalone/` が完全に空だった。** 一方 `pages-manifest.json` は `.next/server/` に**存在していた**。ファイルが作られていないのではなく、アダプタが見る場所に無い
2. **仮説①「Turbopackが standalone を出さない」→ 否定。** `output: "standalone"` を明示すれば Turbopack でも `.next/standalone/.next/server/pages-manifest.json` まで出た
3. **アダプタの実装を読んだ。** `@opennextjs/aws/dist/build/buildNextApp.js`：
   ```js
   export function setStandaloneBuildMode(options) {
       // Equivalent to setting `output: "standalone"` in next.config.js
       process.env.NEXT_PRIVATE_STANDALONE = "true";
   }
   ```
   `output` を書き換えるのではなく、**私的な環境変数を立ててから `execSync` で `next build` を叩いている**
4. **仮説②「Next.js 16 がこの私的環境変数を無視する」→ 否定。** `NEXT_PRIVATE_STANDALONE=true` を手で立てると Turbopack でも webpack でも standalone が出た。アダプタが実際に叩くコマンド（`bun run build`）でも出た
5. **`setStandaloneBuildMode` は無条件で呼ばれていた**（`@opennextjs/cloudflare/dist/cli/build/build.js:62`）。呼ばれているのに効かない
6. → 残った差は**アダプタ自身を走らせているランタイム**。`npx`（Node）で走らせたら、`output` 未設定のまま exit=0・worker.js 生成（実験C）

**確定した原因：Bun ランタイム下では、アダプタが起動後に行う `process.env` の変更が `child_process.execSync` の子プロセスへ伝わらない。** そのため Next は standalone モードに入らず、失敗はずっと後の `createCacheAssets` で ENOENT として表面化する。エラーメッセージが原因から遠いのが、この問題が分かりにくい理由。

## 4. 使う側にとっての結論

**アダプタは Node で走らせる。**

```bash
npx opennextjs-cloudflare build     # 通る
bunx --bun opennextjs-cloudflare build   # 落ちる
```

Bun を使いたい場合の回避策は `next.config.ts` に1行：

```ts
const nextConfig: NextConfig = { output: "standalone" };
```

ただしこれは**原因の除去ではなく症状の回避**であることを理解して使う。

⚠ **静的書き出し（`output: "export"`）とは別条件。** OpenNext は Workers 上でSSRを動かす経路なので `export` とは併用できない。単純な静的サイトなら OpenNext を使わず `output: "export"` → Cloudflare Pages が最短。

## 8. 追試 — Bun側はバグで、修正はまだ出荷されていない（2026-08-15）

### 最小再現（20行・`bun-env-probe.mjs`）

起動後に `process.env.PROBE_AFTER_START = "true"` を立て、子プロセスから読めるかだけを見る。

| API | Node v26.4.0 | **Bun 1.3.14** |
|---|---|---|
| `execSync`（env省略） | `true` | **(未伝播)** |
| `spawnSync`（env省略） | `true` | **(empty)** |
| `execFileSync`（env省略） | `true` | **ERROR（コマンド失敗）** |

`process.env` を自分で読むと Bun でも `true` と返る。**プロセス内では立っているのに、子には渡っていない。**

### 回避策は効く（`bun-env-probe-workaround.mjs`）

| | Bun 1.3.14 |
|---|---|
| `execSync(cmd)` | (未伝播) |
| `execSync(cmd, { env: process.env })` | **true** |
| `spawnSync(cmd, args, { env: process.env })` | **true** |

→ **OpenNext 側の恒久修正は1箇所。** `@opennextjs/aws` の `buildNextjsApp()` が
`cp.execSync(command, { stdio, cwd })` に `env: process.env` を足せば、Bunでも通る。
